1. Если у каталога project будут права g=x, то alice сможет прочитать notes.txt, если точно знает имя файла и у самого файла есть право на чтение для неё. Право x на каталог позволяет обращаться к файлам внутри по известному имени. Но посмотреть список файлов через ls она не сможет, потому что для этого нужно право r на каталог.
2. При команде cp report.txt /home/alice/ группой новой копии, скорее всего, будет alice, а не developers. Причина в том, что cp создаёт новый файл уже в каталоге /home/alice. Setgid влияет на новые файлы только в том каталоге, где он установлен. Поэтому группа developers у исходного файла не обязана сохраниться при обычном копировании.
3. nologin запрещает обычный интерактивный вход под пользователем webapp. Точечное правило sudo разрешает ему выполнять от root только конкретную команду, например перезапуск своего сервиса. Если приложение взломают и злоумышленник получит выполнение команд от имени webapp, nologin сам по себе это не остановит, но возможности повышения привилегий будут ограничены разрешённой sudo-командой. Если же добавить webapp в группу sudo, возможный взлом будет намного опаснее, потому что пользователь получит гораздо более широкие возможности выполнять команды от root.
4. Для самого владельца webapp переход с прав 700 на 777 дополнительных прав не даёт. При 700 у владельца уже есть rwx, и при 777 у него остаются те же rwx. Разница в том, что при 777 полный доступ получают также группа и все остальные пользователи. Поэтому опасность не только в третьей триаде. По сравнению с 700 права появляются и у группы, и у остальных пользователей системы.
